# nsweb

Librerías del proyecto NetSurf, con licencia MIT (ver el COPYING de cada una), que usa el navegador
de Cloud3DS para leer páginas web:

| Librería | Para qué | Commit |
| --- | --- | --- |
| libhubbub | analizar HTML5 | 6651b8c |
| libdom | el árbol del documento (DOM) | f69781e |
| libparserutils | entrada, codificaciones y utilidades | 6b0cbf0 |
| libwapcaplet | cadenas internadas | c7c128d |
| libcss | analizar CSS y calcular el estilo de cada elemento | bc6a32f |

Origen: https://github.com/netsurf-browser — solo `src/`, `include/` y el enlace hubbub de libdom.
`libparserutils/src/charset/aliases.inc`, `libhubbub/src/tokeniser/entities.inc` y
`libhubbub/src/treebuilder/autogenerated-element-type.c` vienen ya generados (con los scripts Perl y
gperf de cada librería). En libcss, los `src/parse/properties/autogenerated_*.c` salen de
`css_property_parser_gen.c` y `properties.gen`, y los `src/select/autogenerated_*` de
`select_generator.py`; en ellos `(css_fixed_or_calc)0` se cambió por `(css_fixed_or_calc)(css_fixed)0`
porque en ARM `int32_t` no es `int` y GCC no acepta el molde a la unión. En `libhubbub/src/treebuilder/in_body.c` se añadió que `<source>`, `<track>` y `<keygen>` son
elementos vacíos (esta versión no los conoce y metía lo de después, como la `<img>` de un `<picture>`,
dentro de ellos). El navegador de NetSurf en sí es GPL-2.0 y no se usa.
